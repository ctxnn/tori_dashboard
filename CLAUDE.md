# Torii — notes for working in this repo

- Next.js 16 App Router + TypeScript; SQLite via built-in `node:sqlite` (Node 22.13+). No ORM: raw SQL in `src/lib/domain/*`.
- All business rules live in `src/lib/domain`; pages read through it, mutations go through `src/app/api/*` route handlers that call `requireApiUser(...)`.
- Money is integer paise; percentages are basis points. Never use floats for money.
- Campaign versions are immutable once submitted; approvals bind to `content_hash`. Don't add code paths that mutate a non-draft version.
- Payments only change through `receiveProviderEvent` (idempotent). Ledger writes use `INSERT OR IGNORE` with an idempotency key.
- `npm test` runs the workflow suite against a temp data dir. The dev server may miss new route folders until restarted.
- Three route groups share the root layout: `(studio)` (workspace, header/footer chrome), `(fan)` (phone app shell) and `(partner)` (Partner Portal). URLs don't include the group names.
- The fan app and Partner Portal live in `src/store/*` (lib, components, data). Their state is one JSON document read and written with `read()` / `mutate()` from `src/store/lib/db.ts` (table `store_state`). Store prices are integer **rupees**, not paise; convert at the boundary (`src/store/lib/collabs.ts` is the bridge into the workspace domain).
- Store styles are scoped to `.store-root` in `globals.css`, which re-points shared Tailwind tokens (card, ink, paper, ok, warn, font-sans, font-display). Wrap any store component rendered outside the `(fan)`/`(partner)` layouts in `.store-root`, with `data-section` on a descendant.
- Store and partner sessions fall back to the demo person from `/switch` (`studioId` / `studioIds` links in `scripts/store/seed.ts`). Regenerate `src/store/data/*.json` with `npm run store:seed`.
- The workspace and Partner Portal have two looks: "new" (default) and "classic", picked by the `torii_ui` cookie (`src/lib/ui-mode.ts`, toggled via `/api/ui`). `<html data-ui>` carries it. New-look code lives in `src/components/v2/*` and `src/app/v2.css` (all rules scoped to `[data-ui="new"]`); layouts and the landing page branch on `uiMode()`. Keep classic markup working: style it from `v2.css` through the `ui-*` hooks rather than editing it, and keep fan-app rules in v2.css scoped to `[data-ui="new"] .store-app` (or `.fan-skin` for previews) so Classic restores the original fan app.
- Japanese (日本語) covers the IP owner's workspace pages and the Partner Portal only (`torii_lang` cookie, `/api/lang`). Write copy as `t("English", "日本語")` using `getT("owner" | "partner")` on the server or `useT()` in client components; shared components take an optional `t` prop. Use polite business Japanese (です・ます, honorifics toward publishers). Generated text that owners read (rule checks, audience findings, statement checks) carries a `ja` copy.
